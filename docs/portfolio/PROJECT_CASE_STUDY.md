# PlanBranch: keeping intent and authority visible in AI-assisted coding

PlanBranch is a local visual workspace for directing and reviewing coding agents. Its motivating hypothesis is that complex AI-assisted projects become harder to control when the original request, evolving plan, agent changes and test evidence are spread across conversations. This motivation was supplied by the project owner for this audit; specific personal incidents and the development timeline still need owner confirmation.

The central design is a sequence of distinct decisions: **intent → plan → approved task → authorized execution → observed changes → verification → human review → application**. A model proposing a change does not authorize that change. A process exiting successfully does not prove that acceptance criteria were tested. Accepting a candidate does not apply it to the working checkout or make a commit.

The executable application combines a React/TypeScript diagram workspace with a Python/Flask backend and SQLite persistence. Users can record requirements, constraints and alternatives; connect implementation tasks to diagram elements; define acyclic prerequisites; and inspect candidate changes in isolated Git worktrees. Diagram edges can represent loops, while task prerequisites describe execution order. Planning supports several local or cloud providers. Repository excerpts require explicit transmission consent, and code execution has its own approval boundary.

Visualisation makes relationships inspectable, but the engineering contribution extends beyond drawing a flowchart. Semantic task scopes distinguish meaningful requirement changes from layout edits. Source identities bind reviews to specific candidates. Stored approvals, execution records and application receipts preserve distinctions that a single “done” label would hide. Importing a plan or restoring an alternative does not revive execution authority. These mechanisms support human oversight; they do not guarantee good human decisions or correct model output.

The audit found a timing gap between run preparation and agent launch: task or prerequisite progress could change without invalidating semantic approval. The targeted correction rechecks readiness at that boundary. It also corrected overlapping status polls that could leave a finished run displayed as running. The offline walkthrough now explains that its validation change leaves a dependent counting task unfinished. No database migration, provider expansion or architectural rewrite was needed.

Reproducible evidence comprises automated boundary tests, an offline demonstration, and fixed evaluation tasks using disposable repositories. Actual check outcomes and platform gaps are recorded in the [validation record](VALIDATION.md) and [evidence register](EVIDENCE_REGISTER.md). Scripted edits are labelled as fixtures. A controlled comparison of direct AI coding against PlanBranch, including human review time and error detection, is **not yet conducted**. No productivity, accuracy, adoption or safety improvement is claimed.

The owner supplied the problem framing and requested this engineering audit. This audit's implementation, tests and documentation were produced with AI coding assistance and require the owner's review. Repository history alone cannot establish who conceived each design or independently wrote each function. Before presenting the project, the owner should identify the decisions they made, code they understand and debugged, and work delegated to AI or collaborators.

Remaining questions include whether the additional review steps help novices, whether evidence links improve detection of unwanted changes, and when the workflow costs more effort than it saves. Requirements currently have paragraph-level identity, checks do not prove complete correctness, and worktree separation depends on additional command isolation. These limitations make PlanBranch a credible systems engineering investigation with a testable research direction.
